Для компиляции Python-программы (`.py`) в исполняемый файл Linux с помощью **Nuitka** рекомендую выполнять компиляцию непосредственно в Ubuntu.

Nuitka преобразует Python-код в C/C++-код, а затем использует системный C-компилятор для создания исполняемого файла.

Важный момент: если программа предназначена для Ubuntu, лучше компилировать её именно в Ubuntu, а не в Windows. Это позволит получить исполняемый файл, совместимый с соответствующей Linux-средой.

## **1. Подготовка Ubuntu**

Установи необходимые инструменты:

```
sudo apt update

sudo apt install python3 python3-pip python3-venv
sudo apt install build-essential
```

`build-essential` устанавливает GCC, G++ и другие необходимые инструменты сборки.

## **2. Установка Nuitka**

Рекомендую устанавливать Nuitka в виртуальное окружение:

```
python3 -m venv ~/nuitka-env
source ~/nuitka-env/bin/activate

python -m pip install --upgrade pip
python -m pip install nuitka
```

Проверить установку:

```
python -m nuitka --version
```

Именно запуск через `python -m nuitka` удобен тем, что позволяет однозначно использовать Nuitka из активного окружения Python.

## **3. Компиляция Python-файла**

Предположим, у тебя есть файл:

```
/home/user/project/main.py
```

Есть три основных режима компиляции.

### **Вариант А. Обычная компиляция**

```
python -m nuitka main.py
```

Создаётся исполняемый файл, но он продолжает зависеть от установленного Python и используемых библиотек.

Этот вариант подходит для запуска на той же системе, где выполнялась компиляция.

### **Вариант Б. Standalone — автономная программа**

```
python -m nuitka --mode=standalone main.py
```

Nuitka создаст каталог:

```
main.dist/
```

Внутри будет исполняемый файл `main` и необходимые ему библиотеки.

Преимущества:

- На целевом компьютере не обязательно устанавливать Python.
- Не требуется устанавливать используемые Python-пакеты.
- Можно перенести каталог `main.dist` на другой компьютер.

Это хороший вариант для распространения программы.

### **Вариант В. Onefile — один исполняемый файл**

```
python -m nuitka --mode=onefile main.py
```

В результате получается один исполняемый файл.

Преимущества:

- Удобно переносить.
- Не нужно распространять отдельный каталог с библиотеками.
- Python на целевой машине не нужен.

При запуске программа распаковывает необходимые компоненты во временный каталог.

**Моя рекомендация:** сначала используй `standalone`, проверь работоспособность программы, а затем переходи на `onefile`. Так проще обнаруживать проблемы с отсутствующими зависимостями.&#x20;

## **4. Дополнительные параметры**

Например, можно задать имя итогового файла и каталог сборки:

```
python -m nuitka \
    --mode=onefile \
    --output-dir=dist \
    --output-filename=myprogram \
    main.py
```

Результат:

```
dist/
    myprogram
```

Можно также включить дополнительные файлы, например конфигурацию:

```
python -m nuitka \
    --mode=standalone \
    --include-data-files=config.ini=config.ini \
    main.py
```

Обрати внимание: обычные файлы данных (TXT, CSV, INI и т. д.) не всегда включаются автоматически. Их нужно добавлять отдельно.&#x20;

## **5. Запуск полученного файла**

Для `onefile`:

```
chmod +x myprogram
./myprogram
```

Для `standalone`:

```
cd main.dist
chmod +x main
./main
```

## **6. Важные особенности Linux**

Есть несколько моментов, которые стоит учитывать.

**1. Архитектура процессора**

Компиляция выполняется под архитектуру текущей системы. Например:

- Ubuntu x86_64 → исполняемый файл для x86_64.
- Ubuntu ARM64 → исполняемый файл для ARM64.

**2. Совместимость с другими версиями Ubuntu**

Даже `standalone` и `onefile` не гарантируют абсолютную независимость от Linux. Могут оставаться зависимости от системных библиотек, например glibc.

Если планируется запуск на разных компьютерах, желательно собирать программу на самой старой версии Ubuntu, которую предполагается поддерживать.

**3. Сторонние библиотеки**

Nuitka умеет обрабатывать импорты Python-модулей, включая `pandas`, `numpy` и другие библиотеки. Однако динамические импорты и дополнительные файлы данных могут потребовать специальных параметров.

**4. Проверка зависимостей**

После компиляции можно проверить динамические библиотеки:

```
ldd main.dist/main
```

Это поможет обнаружить отсутствующие системные библиотеки.

## **Уточнение для выбора оптимального способа компиляции**

Есть один важный вопрос: **где ты планируешь запускать полученный исполняемый файл?**

- На том же компьютере с Ubuntu.
- На других компьютерах с Ubuntu, где Python не установлен.
- На разных Linux-дистрибутивах (Ubuntu, Debian и т. д.).

От этого зависит, какой режим Nuitka лучше использовать и насколько автономным получится исполняемый файл.
